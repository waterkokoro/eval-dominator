# 评测服务协议

## 调用方向

`Go backend -> Python Core`

协议文件：

- `proto/eval_service.proto`

## 设计原则

- `EvalService` 只提供 OpenCompass 原子能力。
- Go 后端负责业务任务创建、状态推进、超时、重试、结果入库和前端查询。
- Core 不维护业务状态，不连接 SQLite。
- 不设计同步跑完整个长任务的 `RunEvaluation` 大接口。
- Core 返回尽量完整的指标、原始结果路径、报告路径、日志路径和错误详情。

## 方法定义

### HealthCheck

用途：确认 Python Core 服务可用。

请求：

- `request_id`：请求追踪 ID。

响应：

- `ok`：服务是否可用。
- `service`：服务名称。
- `version`：服务版本。
- `message`：补充说明。

### ValidateEvalConfig

用途：校验评测配置是否具备执行条件。

请求：

- `request_id`：请求追踪 ID。
- `config`：标准化评测配置。

响应：

- `valid`：配置是否有效。
- `errors`：字段级校验错误。

### BuildEvalConfig

用途：将标准化请求转换为 OpenCompass 可执行配置。

请求：

- `request_id`：请求追踪 ID。
- `config`：标准化评测配置。

响应：

- `ok`：是否构建成功。
- `config_path`：生成的 OpenCompass 配置路径。
- `output_dir`：任务输出目录。
- `artifacts`：配置产物引用。
- `error`：错误详情。

### ExecuteEval

用途：执行一次 OpenCompass 评测能力。

说明：该方法只是 Core 原子执行能力，不代表业务任务生命周期。Go 后端必须在调用前后维护任务状态。

请求：

- `request_id`：请求追踪 ID。
- `eval_task_id`：Go 后端生成的任务 ID。
- `config`：标准化评测配置。
- `config_path`：可选的 OpenCompass 配置路径。
- `output_dir`：输出目录。

响应：

- `ok`：是否执行成功。
- `output_dir`：输出目录。
- `artifacts`：执行产物引用。
- `error`：错误详情。

### ParseEvalResult

用途：解析 OpenCompass 输出产物。

请求：

- `request_id`：请求追踪 ID。
- `eval_task_id`：Go 后端生成的任务 ID。
- `output_dir`：OpenCompass 输出目录。

响应：

- `ok`：是否解析成功。
- `result`：标准化评测结果。
- `error`：错误详情。

## 核心数据结构

### EvalConfig

- `model`：模型配置。
- `dataset`：数据集配置。
- `runtime`：运行配置。
- `extra_params`：扩展参数。

### ModelConfig

- `type`：模型类型，MVP 使用 `MODEL_TYPE_REMOTE_API`。
- `provider`：模型服务提供商。
- `model_name`：模型名称。
- `base_url`：远程 API 地址。
- `api_key`：API Key，由 Go 后端传入 Core，Core 不持久化。
- `params`：模型参数。

### DatasetConfig

- `type`：数据集类型，MVP 使用 `DATASET_TYPE_OPENCOMPASS_DEMO`。
- `name`：数据集名称。
- `path`：数据集路径。
- `params`：数据集参数。

### EvalResult

- `metrics`：指标列表。
- `artifacts`：产物列表。
- `raw_result_path`：原始结果路径。
- `report_path`：报告路径。
- `log_path`：日志路径。
- `metadata`：补充元数据。

## 兼容规则

- 新增字段必须使用新编号。
- 删除字段后不得复用字段编号。
- 枚举新增值只能追加。
- 文档变更必须跟随 `.proto` 变更。
