# 整体架构说明

## 版本说明

- 文档版本：2026-04-27 v1
- 当前状态：作为后续工程实现的主方案
- 历史材料：`md/init.md` 仅作为第一版讨论记录，不再作为实现依据

## 固定技术方案

- 前端：`Vue2 + ElementUI + Axios + Vue Router`
- Go Web 后端：`Go + Gin + SQLite + gRPC Client`
- Python Core：`Python + gRPC Server + OpenCompass`
- 通信方式：前端通过 HTTP 调 Go 后端，Go 后端通过 gRPC 调 Python Core
- 本地部署：前端、Go 后端、Python Core 三个进程分别启动

## 职责边界

### 前端

前端只负责页面交互，不直接调用 Python Core：

- 登录页
- 评测提交页
- 评测结果页
- 任务历史页后续迭代
- API Key 输入支持“仅本次使用”和“保存到数据库”

### Go Web 后端

Go 后端是唯一业务编排方：

- 用户登录与 JWT 鉴权
- 任务创建、任务状态推进、失败处理、超时控制
- SQLite 数据持久化
- API Key 保存、脱敏返回和敏感日志规避
- 调用 Python Core 的 gRPC Client 管理
- 对前端提供 HTTP API

Go 后端不直接实现 OpenCompass 评测逻辑。

### Python Core

Python Core 是无状态能力服务：

- 不维护业务任务状态
- 不连接 SQLite
- 不做用户登录、权限、前端字段适配
- 不负责任务流程编排
- 只封装 OpenCompass 的原子能力

Core 优先提供最小维度能力，例如：

- 健康检查
- 构建或校验评测配置
- 执行 OpenCompass 评测能力
- 解析 OpenCompass 输出结果
- 返回指标、原始结果路径、日志路径、报告路径、错误详情

除非多步封装能明显提升性能或维护性，否则不把复杂流程封装到 Core 中。

## MVP 评测闭环

MVP 第一条评测链路固定为：

- 远程 API 模型
- OpenCompass demo 数据集
- 用户输入 API Key
- API Key 允许保存到数据库
- Python Core 尽量返回 OpenCompass 可解析的完整指标和产物引用

后续需要平滑扩展到标准数据集，因此 MVP 的字段设计不能只绑定 demo 数据集。

## 接口契约

### Go 后端到 Python Core

必须使用 `proto/` 下的 `.proto` 文件作为唯一真实契约。

建议服务名：

- `EvalService`

建议核心能力：

- `HealthCheck`
- `ValidateEvalConfig`
- `BuildEvalConfig`
- `ExecuteEval`
- `ParseEvalResult`

不设计一个同步跑完整个长任务的 `RunEvaluation` 大接口。即使存在执行接口，也只代表 Core 的原子执行能力，由 Go 后端控制调用时机、状态和结果入库。

### 前端到 Go 后端

MVP 阶段先维护 HTTP 接口文档，建议位置：

- `backend/docs/http接口文档.md`

后续可升级为 OpenAPI。

## 命名规范

统一术语：

- 司南统一写作 `OpenCompass`
- 评测统一使用 `Eval`
- 评测任务统一使用 `EvalTask`
- 评测结果统一使用 `EvalResult`
- gRPC 服务统一使用 `EvalService`

各语言命名：

- Go 文件名使用小写下划线，例如 `eval_service.go`
- Python 文件名、函数名、变量名使用 `snake_case`
- Vue 组件文件使用 `PascalCase.vue`，例如 `EvalForm.vue`
- Proto 字段使用 `snake_case`
- 数据库表和字段使用 `snake_case`
- HTTP JSON 字段使用 `camelCase`

Markdown 文档尽量使用中文命名；需要版本区分时使用日期和版本号，例如：

- `整体架构说明-2026-04-27-v1.md`
- `接口文档-2026-04-27-v2.md`

不使用随机字符串、MD5、UUID 作为手写文档文件名。

## 后端分层

Go 后端固定使用轻量 DDD 分层：

- `handler`：HTTP 入参绑定、鉴权上下文提取、响应返回
- `application`：业务用例、任务编排、事务边界
- `domain`：实体、枚举、状态流转、领域规则
- `infrastructure`：SQLite、gRPC Client、配置、日志

重资源必须单例或集中初始化：

- 数据库连接
- gRPC Client
- 配置实例
- 日志实例

## 配置规范

所有可配置项必须进入配置文件或环境变量示例，不允许硬编码在业务代码中。

建议配置文件：

- `backend/config/config.example.yaml`
- `core/config/config.example.yaml`
- `frontend/.env.development.example`
- `frontend/.env.production.example`

配置至少覆盖：

- HTTP 地址
- gRPC 地址
- SQLite 路径
- JWT 配置
- 日志目录
- OpenCompass 路径
- 数据集路径
- 任务输出目录
- 超时时间
- API Key 存储相关配置

## 本地目录规划

- `frontend/`：Vue2 前端工程
- `backend/`：Go Web 后端工程
- `core/`：Python Core 工程
- `proto/`：gRPC 协议文件
- `scripts/`：启动、初始化、联调脚本
- `deploy/`：部署说明和配置示例
- `runtime/`：运行期产物、日志、SQLite、任务输出
- `resources/`：本地资料说明、示例数据说明、OpenCompass 外部资源说明
- `md/`：中文方案、架构、计划文档
