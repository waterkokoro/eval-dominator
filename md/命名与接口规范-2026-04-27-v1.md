# 命名与接口规范

## 统一术语

- 司南统一写作 `OpenCompass`。
- 评测统一使用 `Eval`。
- 评测任务统一使用 `EvalTask`。
- 评测结果统一使用 `EvalResult`。
- gRPC 服务统一使用 `EvalService`。
- Python Core 对外统一称为 `Core` 或 `OpenCompassCore`。

禁止使用：

- `SiNan`
- `Sinan`
- `OCompass`
- `EvaluationTask`
- `EvaluationResult`

## 代码命名

### Go

- 文件名：小写下划线，例如 `eval_service.go`。
- 包名：小写短名。
- 导出类型和方法：`PascalCase`。
- 非导出变量和方法：`camelCase`。

### Python

- 文件名、模块名、函数名、变量名：`snake_case`。
- 类名：`PascalCase`。
- 常量：`UPPER_SNAKE_CASE`。

### Vue

- 组件文件：`PascalCase.vue`，例如 `EvalForm.vue`。
- 目录名：小写短横线，例如 `eval-task`。
- 变量和方法：`camelCase`。

### Proto

- service、message、enum：`PascalCase`。
- 字段名：`snake_case`。
- 枚举值：`UPPER_SNAKE_CASE`。

### 数据库

- 表名：`snake_case`。
- 字段名：`snake_case`。

### HTTP JSON

- 字段名：`camelCase`。
- 后端 DTO 负责 JSON 字段和数据库/proto 字段之间的转换。

## 文档命名

Markdown 文档尽量使用中文命名。

推荐格式：

- `整体架构说明-2026-04-27-v1.md`
- `实施步骤-2026-04-27-v1.md`
- `命名与接口规范-2026-04-27-v1.md`

禁止手写文档使用：

- 随机字符串
- MD5
- UUID
- 无意义缩写

## 接口维护规则

### gRPC

- `proto/eval_service.proto` 是 Go 后端和 Python Core 的唯一真实契约。
- `proto/评测服务协议.md` 只解释协议，不替代 `.proto`。
- 修改 `.proto` 后必须同步更新协议说明。
- 删除字段后不得复用字段编号。

### HTTP

- `backend/docs/http接口文档.md` 是前端调用后端的接口文档。
- 新增或修改 HTTP API 前，必须先更新接口文档。
- 请求和响应必须包含字段说明和示例。

## 配置命名

- 后端示例配置：`backend/config/config.example.yaml`
- Core 示例配置：`core/config/config.example.yaml`
- 前端开发示例配置：`frontend/.env.development.example`
- 前端生产示例配置：`frontend/.env.production.example`

真实配置文件不得提交 Git。

## 多语言（i18n）约定

前端基于 `vue-i18n@8`（Vue 2 兼容线）+ ElementUI 内置 locale，文案集中在 `frontend/src/locales/{zh-CN,en-US}/*.json`，按业务模块分文件（`common / auth / eval / model / dataset / system / errors`）。中文为默认语言，英文为可选；新增语言只需在 `frontend/src/locales/index.js` 的 `LANGUAGES` 注册一项。

### 后端错误 code 与前端 errors.json 同步

- 后端响应统一形如 `{ "code": "INVALID_ARGUMENT", "message": "..." }`，`code` 是稳定枚举，是跨端真理；`message` 仅作 fallback 给非前端调用方（curl 等）。
- 新增或重命名一个 `code` 时，必须同步在 `frontend/src/locales/zh-CN/errors.json` 与 `frontend/src/locales/en-US/errors.json` 各加一条 key 完全等于 `code` 的文案。前端 `src/api/http.js` 的 `resolveApiErrorMessage` 会优先读 `errors.<CODE>`，未命中才回退后端 `message`。
- 已纳入字典的 `code` 不得修改语义；要变义请用新 code，避免老前端误显示。

### 文案撰写规则

- 所有面向用户的字符串必须走 `$t('namespace.key')` / `i18n.t(...)`，禁止在 `.vue` 模板或 JS 业务代码里硬编码任何具体语言的文案（注释除外）。
- 命名空间按业务模块切分，单文件控制在 200 行以内便于 fork 合并。
- 状态/类型这类枚举的文案，用 `eval.status.<status>`、`dataset.type.<type>` 等 key 化结构存放，业务侧通过 `getEvalStatusText` 等帮助函数查询，不要在 JS 常量里硬编码字符串。
