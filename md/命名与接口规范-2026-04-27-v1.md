# 命名与接口规范

## 统一术语

- 司南统一写作 `OpenCompass`。
- 评测统一使用 `Eval`。
- 评测任务统一使用 `EvalTask`。
- 评测结果统一使用 `EvalResult`。
- gRPC 服务统一使用 `EvalService`。
- Python Core 对外统一称为 `Core` 或 `OpenCompassCore`。

禁止使用：

- `SiNan`
- `Sinan`
- `OCompass`
- `EvaluationTask`
- `EvaluationResult`

## 代码命名

### Go

- 文件名：小写下划线，例如 `eval_service.go`。
- 包名：小写短名。
- 导出类型和方法：`PascalCase`。
- 非导出变量和方法：`camelCase`。

### Python

- 文件名、模块名、函数名、变量名：`snake_case`。
- 类名：`PascalCase`。
- 常量：`UPPER_SNAKE_CASE`。

### Vue

- 组件文件：`PascalCase.vue`，例如 `EvalForm.vue`。
- 目录名：小写短横线，例如 `eval-task`。
- 变量和方法：`camelCase`。

### Proto

- service、message、enum：`PascalCase`。
- 字段名：`snake_case`。
- 枚举值：`UPPER_SNAKE_CASE`。

### 数据库

- 表名：`snake_case`。
- 字段名：`snake_case`。

### HTTP JSON

- 字段名：`camelCase`。
- 后端 DTO 负责 JSON 字段和数据库/proto 字段之间的转换。

## 文档命名

Markdown 文档尽量使用中文命名。

推荐格式：

- `整体架构说明-2026-04-27-v1.md`
- `实施步骤-2026-04-27-v1.md`
- `命名与接口规范-2026-04-27-v1.md`

禁止手写文档使用：

- 随机字符串
- MD5
- UUID
- 无意义缩写

## 接口维护规则

### gRPC

- `proto/eval_service.proto` 是 Go 后端和 Python Core 的唯一真实契约。
- `proto/评测服务协议.md` 只解释协议，不替代 `.proto`。
- 修改 `.proto` 后必须同步更新协议说明。
- 删除字段后不得复用字段编号。

### HTTP

- `backend/docs/http接口文档.md` 是前端调用后端的接口文档。
- 新增或修改 HTTP API 前，必须先更新接口文档。
- 请求和响应必须包含字段说明和示例。

## 配置命名

- 后端示例配置：`backend/config/config.example.yaml`
- Core 示例配置：`core/config/config.example.yaml`
- 前端开发示例配置：`frontend/.env.development.example`
- 前端生产示例配置：`frontend/.env.production.example`

真实配置文件不得提交 Git。
