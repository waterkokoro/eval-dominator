# 实施步骤

## 第一阶段：最小闭环

目标：验证 `Vue -> Go backend -> Python Core -> OpenCompass` 链路可用。

1. 固化工程说明文档。
2. 固化 `proto/eval_service.proto` 和 `proto/评测服务协议.md`。
3. 固化 `backend/docs/http接口文档.md`。
4. 初始化 Python Core，先实现 `HealthCheck`。
5. 在 Core 中验证远程 API 模型 + OpenCompass demo 数据集。
6. 初始化 Go 后端，加载配置、连接 SQLite、创建 gRPC Client 单例。
7. Go 后端实现 JWT 登录和任务表状态流转。
8. Go 后端调用 Core 的健康检查和评测原子能力。
9. 前端实现登录页、评测提交页、结果查看页的最小可用版本。

## 第二阶段：MVP 完整功能

目标：用户可以登录、提交远程 API 模型评测、查看状态和结果。

1. 前端提交模型服务商、模型名、base_url、API Key、是否保存 API Key。
2. Go 后端创建 `EvalTask`，状态为 `pending`。
3. Go 后端调 Core 校验配置，失败则状态变为 `failed`。
4. Go 后端调 Core 构建 OpenCompass 配置。
5. Go 后端调 Core 执行评测，状态变为 `running`。
6. Go 后端调 Core 解析结果，保存 `EvalResult`。
7. Go 后端将任务状态推进到 `succeeded` 或 `failed`。
8. 前端轮询任务状态并展示指标、报告路径、日志路径、错误信息。

## 第三阶段：一期增强

目标：提升可维护性和基础体验。

1. 增加任务历史列表。
2. 增加 API Key 管理页面或配置入口。
3. 支持 OpenCompass 标准数据集。
4. 增加失败重试和超时取消。
5. 增加更完整的日志查看和产物下载。
6. 补充部署脚本和本地快速启动说明。

## 任务状态机

- `pending`：任务已创建，等待执行。
- `validating`：Go 后端正在调用 Core 校验配置。
- `building`：Go 后端正在调用 Core 构建 OpenCompass 配置。
- `running`：Go 后端正在调用 Core 执行评测。
- `parsing`：Go 后端正在调用 Core 解析结果。
- `succeeded`：任务完成。
- `failed`：任务失败。
- `timeout`：任务超时。

状态推进只允许由 Go 后端完成，Python Core 不维护业务状态。
