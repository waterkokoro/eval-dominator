# 评测角色 / 评测模板 规划（草案）

更新时间：2026-04-27

## 1. 目标

当前评测：**1 任务 = 1 模型 × 1 数据集**。

升级目标：**1 任务 = 1 模板（多角色编排） × 1 数据集**。

典型用例：

- **生成 + 评判（LLM-as-Judge）**：actor 模型生成回答，judge 模型对回答打分。
- **生成 + 校验**：actor 生成 → verifier 检查事实/格式 → 给出汇总。
- **多 actor 对比**：模板中 `actor_a` / `actor_b` 都填入不同预设模型，做 head-to-head。

UI 期望：

> 用户在「提交评测」页选模板 → 页面动态渲染该模板要求的所有角色 → 每个角色挑选一个**预设模型**或在线手填 → 提交。

## 2. 核心概念

| 名称 | 含义 |
| --- | --- |
| 角色 Role | 模板里的一个槽位（slot），有名称/能力描述，运行时绑定一个 model preset 或临时 model |
| 模板 Template | 一组角色定义 + 每角色的可选默认行为（system prompt、生成参数等） + 与之兼容的数据集类型 |
| 角色绑定 RoleBinding | 任务级：角色 → model preset id（或临时模型） |

约束：

- 模板里所有角色共享一份数据集。
- 每个角色独立超时与 QPS（继承模板默认值）。

## 3. 数据库 Schema（建议）

### 3.1 `eval_templates`

```sql
CREATE TABLE eval_templates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    code TEXT NOT NULL UNIQUE,           -- 'judge_baseline' / 'pairwise_battle' 等英文 key
    name TEXT NOT NULL,                  -- 「带评判的生成评测」
    description TEXT NOT NULL DEFAULT '',
    -- 模板适配的数据集 inference 模式（gen / ppl / 不限）
    supported_inference_modes TEXT NOT NULL DEFAULT 'gen',
    -- 角色定义 JSON 数组：
    -- [{"key":"actor","name":"被评测模型","required":true,"allowMultiple":false,
    --   "systemPrompt":"...","defaultParams":{"temperature":0.0}}]
    roles_json TEXT NOT NULL,
    -- 编排策略 JSON：占位，运行时由 Core 解析
    -- {"orchestrator":"actor_then_judge","judgePrompt":"..."}
    orchestrator_json TEXT NOT NULL DEFAULT '{}',
    is_builtin INTEGER NOT NULL DEFAULT 0,  -- 内置模板不允许删除
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3.2 `eval_task_roles`

```sql
CREATE TABLE eval_task_roles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    eval_task_id TEXT NOT NULL,
    role_key TEXT NOT NULL,              -- 'actor' / 'judge' / 'actor_a' ...
    -- 优先 model_preset_id；为 NULL 则使用本表 inline_* 字段
    model_preset_id INTEGER,
    inline_provider TEXT NOT NULL DEFAULT '',
    inline_model_name TEXT NOT NULL DEFAULT '',
    inline_base_url TEXT NOT NULL DEFAULT '',
    inline_api_key TEXT NOT NULL DEFAULT '', -- 提交后落库；不参与列表展示
    params_json TEXT NOT NULL DEFAULT '{}',  -- 该角色的 temperature / max_out_len 等
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (eval_task_id) REFERENCES eval_tasks(id),
    FOREIGN KEY (model_preset_id) REFERENCES models(id)
);
CREATE INDEX idx_eval_task_roles_task ON eval_task_roles(eval_task_id);
```

### 3.3 `eval_tasks` 增量

```sql
ALTER TABLE eval_tasks ADD COLUMN template_id INTEGER;
ALTER TABLE eval_tasks ADD COLUMN template_code TEXT NOT NULL DEFAULT '';
```

迁移：旧任务无 template_id，认作"裸任务"；前端按现有 UI 走兼容路径。

## 4. API 设计

### 模板 CRUD

- `GET /api/eval/templates`：列出可用模板（含 builtin / 用户自定义）
- `POST /api/eval/templates`：新建
- `PUT /api/eval/templates/:id`：更新（builtin 拒绝）
- `DELETE /api/eval/templates/:id`：删除（builtin 拒绝）

返回示例：

```json
{
  "id": 1,
  "code": "judge_baseline",
  "name": "Actor + Judge",
  "description": "actor 生成回答，judge 模型评分",
  "isBuiltin": true,
  "supportedInferenceModes": ["gen"],
  "roles": [
    {"key":"actor","name":"被评测模型","required":true,"allowMultiple":false},
    {"key":"judge","name":"评判模型","required":true,"allowMultiple":false}
  ]
}
```

### 提交任务（扩展现有 `POST /api/eval/tasks`）

兼容旧请求；新增：

```json
{
  "taskName": "...",
  "templateId": 1,
  "datasetId": 12,
  "roles": [
    {"roleKey":"actor","modelPresetId":3},
    {"roleKey":"judge","modelPresetId":5,"params":{"temperature":0.0}}
  ],
  "runtime": { "...": "..." }
}
```

后端校验：

- 模板里 `required: true` 的角色必须出现且都有可解析的模型；
- 角色与数据集 inference 模式匹配（template.supportedInferenceModes ∋ dataset.inferenceMode）。

旧字段 `provider/modelName/...` 仅在 `templateId` 为空时使用，等价于一个隐藏的 `single_actor` 内置模板。

## 5. 内置模板（首批）

| code | 角色 | 适用 |
| --- | --- | --- |
| `single_actor` | `actor` | 现有"单模型 + 数据集"语义（兜底，可不显式选） |
| `judge_baseline` | `actor`, `judge` | LLM-as-Judge，对生成结果打分 |
| `pairwise_battle` | `actor_a`, `actor_b`, `judge` | 同数据集，两模型对垒，judge 选优 |

## 6. 与 OpenCompass 对接

OpenCompass 原生主要是 actor-only 评测，对多角色支持要走 **subjective evaluation / SubjectiveDataset** 体系（涉及 `LMEvaluator` / `SubjectiveSummarizer`）。建议**两步走**：

### 阶段 1（与本规划一并落地）

- DB / API / UI 全部到位，能保存模板 + 角色绑定 + 任务关联；
- OpenCompass 仍按 **`actor` 角色单跑**：构建 mmengine config 时仅取 `actor`；其它角色仅"挂着"不参与；
- 任务详情新增「角色」tab，展示模板里所有角色 + 当前绑定（即使没参与跑也展示）。

价值：UI 和数据先打通，观察用户如何填，模板是否合理，再做执行端。

### 阶段 2（后续迭代）

- 引入 `core/.../templates/` 模板渲染层，把多角色 → SubjectiveDataset 适配的 OpenCompass config（内含 `infer_cfg` 多模型路由 + `LMEvaluator` 用 judge 模型）。
- `OpenCompassAdapter` 增加 `build_eval_config(role_bindings=...)`，根据 template.code 选择不同的 mmengine 模板。

## 7. 前端 UI 流程

### 提交评测页

1. **顶部**：选「评测模板」（默认 `single_actor`）
2. **模板预览卡片**：显示模板描述 + 角色列表 + 适配的数据集模式（GEN/PPL）
3. **数据集**：仅展示与模板兼容的；不兼容的灰掉并 tooltip 说明
4. **角色配置卡**：模板每个角色一行
   - 选预设模型（同现有「使用预设模型」体验）
   - 折叠区可调 `temperature / max_out_len / qps` 等覆盖参数
   - 可切「手动填写」临时模型
5. **运行参数**：维持现状

### 模板管理页（新增侧边栏入口）

- 列表（code/名称/角色数/适配模式/创建时间）
- 新建：可视化拖拽角色卡片（最简：`+ 添加角色` → 角色 key、显示名、是否必选）
- 内置模板只读，可"复制为自定义"。

### 任务详情页

- 新增「角色绑定」Tab：每个角色名 + 绑定的模型 + 调用过程在 OpenCompass 日志里的引用位置（阶段 2 真正多角色后会更丰富）。

## 9. 兼容性与回滚

- 数据库新增表与新增列均**幂等**（参考已有的 `ensureColumn`）；
- 旧版前端不支持新字段时，后端 `templateId == 0` 走 `single_actor` 等价老逻辑；
- Core 阶段 1 不破坏现有评测能力，可随时回退。

## 10. 待你确认的关键决策

1. **模板权属**：模板是"全局共享"还是"用户私有 + 内置只读"？建议后者，便于本地多账号。
2. **预设模型粒度**：角色绑定时是仅复用模型预设，还是允许 inline 手填？建议保留两种。
3. **judge 评判结果是否要进入 metrics**：阶段 2 完成后，judge 给出的分数也用 `metricDTO.extra.judge="<judge model name>"` 区分。
4. **是否需要"模板版本"**：模板更新会影响历史任务复跑结果对比，建议任务表把 `template_code` 同时落库（已在 §3.3 加），未来需要支持版本号再加 `template_version`。
