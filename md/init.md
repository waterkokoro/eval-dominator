一、司南全能力全景（完整能力清单）

先明确司南库的全部原生能力，作为功能规划的基础，分为 4 大核心模块：

1. 核心评测能力（底层核心）

- 模型对接：支持本地模型加载、远程模型 API 调用

- 数据集管理：内置标准评测数据集、自定义数据集导入

- 评测执行：单任务/批量任务执行、中断/重试机制

- 指标计算：准确率、召回率、F1、困惑度等基础/自定义评测指标

- 流程控制：评测参数配置、流程编排

2. 数据管理能力

- 评测任务数据：任务配置、执行日志、状态记录

- 模型配置数据：模型地址、参数、鉴权信息

- 数据集元数据：数据集名称、格式、样本量

3. 结果分析能力

- 原始结果存储：评测输出原始数据

- 基础统计：指标汇总、得分排行

- 报告生成：文本/表格形式评测报告

- 数据导出：JSON/CSV 格式导出

4. 系统支撑能力

- 配置管理：全局参数、环境配置

- 日志记录：评测日志、系统运行日志

- 异常处理：任务失败、接口报错兜底

5. 非功能需求

1. 轻量：无依赖第三方中间件（仅 SQLite 文件）

2. 易用：本地双击/单命令启动

3. 稳定：评测任务失败有明确报错

4. 简洁：界面无冗余功能，聚焦评测

6. 技术架构

前端（Vue+ElementUI） ←→ 后端 API（Go-Gin） ←→ Core 服务（封装司南库） ←→ SQLite

- 前端：负责页面渲染、接口请求、登录态管理

- 后端：提供 RESTful API、权限校验、数据库操作

- Core 服务：纯逻辑封装，不耦合 Web，只调用司南库实现评测

- SQLite：本地文件数据库，无需安装服务

7. 数据库设计（极简 3 张表）

1. users：用户表（id、用户名、密码、创建时间）

2. tasks：评测任务表（id、用户id、模型API、参数、状态、创建时间）

3. results：评测结果表（id、任务id、指标得分、原始数据、创建时间）

8. 部署方案

1. 本地部署：前端打包 + 后端编译二进制 → 单文件夹运行

2. GitHub：上传完整源码 + 启动脚本 + README 部署文档

9. 交付物

1. 前端源码

2. 后端 + Core 服务源码

3. SQLite 数据库初始化脚本

4. 本地启动脚本

5. GitHub 仓库（V1.0 版本）

6. 部署 README 文档
