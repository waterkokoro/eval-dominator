# 本地部署说明

## 进程组成

本地部署由三个进程组成：

1. Vue 前端
2. Go Web 后端
3. Python Core

## 配置文件

部署前需要从示例配置复制真实配置：

- `backend/config/config.example.yaml` -> `backend/config/config.yaml`
- `core/config/config.example.yaml` -> `core/config/config.yaml`
- `frontend/.env.development.example` -> `frontend/.env.development`

真实配置不得提交 Git。

## 运行资料

需要准备：

- Python 3.10 环境，Core 使用 `core/.venv` 独立虚拟环境。
- OpenCompass 安装来源。
- OpenCompass demo 数据集。
- 至少一个远程 API 模型的调用信息。

## 运行产物

运行产物统一放入 `runtime/`：

- `runtime/logs/`
- `runtime/outputs/`
- `runtime/eval_dominator.db`

## 启动顺序

1. 启动 Python Core。
2. 启动 Go Web 后端。
3. 启动 Vue 前端。

Go 后端启动时应通过 `HealthCheck` 确认 Python Core 可用。

## 快速启动

首次运行先初始化 Core 虚拟环境：

```bash
./scripts/init_core_venv.sh
```

分别打开三个终端，在项目根目录执行：

```bash
./scripts/start_core.sh
```

```bash
./scripts/start_backend.sh
```

```bash
./scripts/start_frontend.sh
```

前端默认访问：

- `http://localhost:8080` 或 Vue CLI 输出的本地地址（端口被占用时会自动退到 8081 等）
- 登录后自动跳转 `/eval/tasks`（任务列表），左侧侧边栏分为「评测中心 / 模型管理 / 数据集 / 系统」四组

后端默认地址：

- `http://127.0.0.1:8080`

Core 默认地址：

- `127.0.0.1:50051`

### 任务名称在列表不显示

需 SQLite 中 `eval_tasks.task_name` 列存在后创建的任务才会落库。请**重启一次 Go 后端**以执行迁移（启动时会先为旧库 `ALTER` 补列，再跑 `001_init.sql`）。补列**之前**创建的任务名称为空属正常，需新建任务后才会显示名称。

### Core 日志中出现 `FD from fork parent still in poll list`

启动评测时 Core 会通过 `subprocess` 调用 OpenCompass，进程会 `fork`，与 gRPC 的 epoll 可能产生 INFO 级提示。仓库已在 `opencompass_core/__main__.py` 与 `scripts/start_core.sh` 中默认设置 `GRPC_ENABLE_FORK_SUPPORT=1`；若仍刷屏，可将 gRPC 日志降为仅错误：`export GRPC_VERBOSITY=error` 后再启动 Core。

## Proto 生成

标准生成方式：

```bash
./scripts/generate_proto.sh
```

该脚本不依赖 macOS 全局 `protoc`：

- Go 侧使用 `buf generate`。
- `buf` 通过 `go install github.com/bufbuild/buf/cmd/buf@latest` 安装。
- `protoc-gen-go` 和 `protoc-gen-go-grpc` 通过 `go install` 安装。
- Python 侧使用 pip 中的 `grpcio-tools`。

如果需要手动安装 Go 侧工具：

```bash
go install github.com/bufbuild/buf/cmd/buf@latest
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
```
